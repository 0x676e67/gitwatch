设置拉取间隔

gitwatch pull ./upstream --url https://github.com/gitwatch/gitwatch.git --every 3600
gitwatch pull ./existing-repo --remote origin --once
gitwatch pull ./existing-repo --strategy merge --every 600
gitwatch pull ./existing-repo --strategy rebase --once

第一条命令会克隆到不存在或为空的目录，然后每小时检查更新。第二条只更新一次已有仓库。--every 的单位是秒。

在桌面应用中添加定时拉取任务，填写目录、远程、间隔和策略。已有仓库可以留空克隆地址。保存后点击启动，任务卡片会显示距离下一次尝试的剩余时间。

选择拉取策略

策略历史分叉时的行为
ff-only · 默认拒绝本次更新，适合希望自行处理历史变化的情况。
merge创建合并提交。如果无需合并，则使用快进更新。
rebase把本地提交重放到远程历史上，会改变提交 ID。适用于尚未分享的提交。

桌面应用在任务表单中提供策略下拉框。TUI 中选中策略字段后，可以按左右方向键或空格切换。合并和变基需要配置 Git 作者身份。

任务策略会覆盖本次拉取的 Git 偏好，但不会修改仓库或全局 Git 配置。没有保存策略的旧任务默认使用 ff-only。

处理拉取失败

工作区有未提交改动时会跳过更新，检测到分支切换后会拒绝继续。gitwatch 不会暂存改动、重置工作区或强制更新。操作结果和错误可以在交互界面的活动记录或 CLI 输出中查看。

网络等普通错误会在设定间隔后重试。如果合并或变基留下未完成操作，任务会停止。请使用 Git 解决并继续，或用对应命令中止：

git merge --abort
# 如果未完成的是变基，则使用：
git rebase --abort

只运行与你要放弃的操作对应的命令。检查仓库状态后，再重新启动任务。

重启与手动执行

桌面应用和 TUI 会保存下次执行时间。重启后会继续剩余倒计时；如果时间已过，会立即执行一次，然后恢复正常间隔。

任务无论是否启动，都可以点击执行一次。已启动任务不会因此创建第二个执行器。手动拉取结束后会重新计时。因未完成 Git 操作而停止的任务，重启应用后也会保持停止。
