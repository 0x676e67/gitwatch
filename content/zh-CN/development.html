CI 在 Windows、macOS 和 Linux 上检查 CLI、TUI、桌面及组合构建。测试使用临时仓库和本地远程。终端界面使用 Ratatui，桌面应用使用 egui/eframe。

可以通过 GitHub issue 反馈问题或提出改进。请提供 gitwatch 版本、操作系统、任务模式、命令或复现步骤，以及相关错误消息。分享日志前，请移除私人路径、远程凭据和文件内容。

发布流程

Release 工作流 构建包含 CLI 和桌面程序的压缩包，并生成 SHA-256 校验文件。目前不包含原生安装程序、签名、公证或自动冲突解决。

v<版本号> 标签需要与 Cargo.toml 一致，并指向 main 上的提交。推送标签后，检查通过即可发布 GitHub Release。Crates.io 使用 release.yml 和 crates-io 环境进行授信发布；已发布的 crate 版本会跳过。新 crate 首次上传需先在本地完成，再配置授信。

预演时，在 Actions 页面运行 Release，关闭 publish。手动发布已有标签时，选择标签并开启 publish。只发布 GitHub Release 时保持 publish_crate 关闭。
