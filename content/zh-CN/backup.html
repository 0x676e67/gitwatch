选择要保存的文件

工作空间备份把指定文件复制到独立的裸 Git 仓库，每个工作空间使用一个分支。源目录不必是 Git 仓库，gitwatch 也不会在源目录中暂存文件或创建提交。

gitwatch workspace add ./project-a --name project-a --include notes.md --include notes
gitwatch workspace add ./project-b --name project-b --include notes.md --include notes
gitwatch workspace list
gitwatch workspace backup project-a
gitwatch workspace watch --all

请替换成自己的目录与文件选择。添加工作空间只保存设置；backup 执行一次备份，watch --all 则持续监听已注册的工作空间。

分支与文件边界

每个备份任务保留稳定的内部 UUID。新任务默认使用任务名作为备份分支，空白转换为连字符，例如 Quic notes 对应 Quic-notes。如果名称不符合 Git 规则，可以单独指定分支。备份包含 manifest.json 和 files/<项目相对路径>。源目录的绝对路径只保存在本地配置中，因此另一台设备可以将同一份备份绑定到不同目录。

可以选择被源项目 Git 规则忽略的文件，但 Git 元数据及已知凭据、缓存路径仍会排除。默认不接受符号链接，可以通过下方的任务选项启用；其他 Windows 重解析点仍不支持。单文件上限为 16 MiB，一次扫描的内容上限为 128 MiB、文件数量上限为 10,000。

选中的文件消失后，会保留并报告它的最后一次备份。整个源目录不可用时会报错，不创建新备份。因此，工作空间备份与监听模式对源文件删除的处理不同。

备份符号链接目标

此选项将包含在下一次发布中；v0.2.0 不接受符号链接。

编辑备份任务时，在桌面界面勾选跟随符号链接，或在 TUI 的对应字段按左右键切换。启用后，会读取链接目标中的实际文件，并按链接在项目中的相对路径保存；目标可以位于项目外。保存的是内容，不是链接本身。源根目录仍须为普通目录。

gitwatch workspace add ./project --name agents --include .agents --follow-links
gitwatch workspace edit agents --follow-links true
gitwatch workspace edit agents --follow-links false

此选项默认关闭，只保存在当前任务的本地配置中，导入备份不会自动启用。排除规则使用项目中可见的路径；定期内容检查会发现外部目标的变化。链接目标不存在时会跳过，该路径以前保存的文件仍保留在备份中。循环链接、无法读取的目标和指向备份数据的链接会报错，已有备份保持不变；凭据与缓存排除规则仍然生效。

恢复预览仍会拒绝经过符号链接的目标路径。需要恢复这些内容时，可以先把备份绑定到另一个普通目录，再预览并确认恢复；恢复后得到普通文件和目录，不会通过链接改写原目标。

配置远程备份仓库

任务还没有备份时，点击上传会自动创建第一份快照，再推送到远端。已有快照时，上传只发送已保存的历史，不会重新扫描源目录；要备份当前改动，请使用执行一次。上传失败会保留本地快照，之后可以重试。启用自动上传后，每次成功备份都会推送分支。

gitwatch workspace remote https://github.com/you/private-backup.git --auto-push
gitwatch workspace fetch

根据备份内容选择适当的远程仓库。只需要本地备份时，可以不配置远程。获取历史不会恢复文件，推送也不会强制覆盖远程。如果历史发生分叉，本地备份仍会保留，需要你手动处理。

任务名称与分支变更

同一应用工作空间中的备份、监听和拉取任务不能重名。名称保留显示大小写，判重时忽略大小写和首尾空白，例如 quic 与 Quic 不能作为两个任务。不同应用工作空间可以使用相同名称。

重命名备份任务时，本地分支和已配置的远端分支会一起迁移，并保留之前的提交。名称中的空白会转换为连字符；转换后的分支如果冲突，会拒绝保存。远端重命名需要网络连接，以及创建新分支、删除旧分支的权限。分支保护和仓库默认分支可能需要先在仓库设置中调整。遇到冲突时保留原绑定。仅修改大小写时，请先改成一个不同的中间名称，再改为目标名称。

已有的 workspaces/<uuid> 绑定仍可使用。要在不更改任务名的情况下迁移分支，可以编辑任务的分支字段，或运行：

gitwatch workspace edit quic --branch quic

先预览，再恢复

在另一台设备配置远程并获取备份分支，然后把工作空间绑定到本地目录：

gitwatch workspace remote https://github.com/you/private-backup.git
gitwatch workspace fetch
gitwatch workspace import agents ./local-project
gitwatch workspace history <uuid>
gitwatch workspace restore <uuid> --preview
gitwatch workspace restore <uuid> --plan <preview-uuid> --show notes.md
gitwatch workspace restore <uuid> --plan <preview-uuid> --confirm

将 <uuid> 替换为工作空间 UUID，将 <preview-uuid> 替换为预览命令返回的 ID。尖括号表示占位符，不要原样输入。导入后工作空间保持暂停，便于先检查历史并恢复文件。

  1. 创建预览，核对将要发生变化的文件。
  2. 使用 --show 查看文件内容，或在桌面界面中检查预览。
  3. 确认准备写入后，再确认这份预览。

预览有效期为 24 小时；目标内容有变化时，需要重新创建预览。替换文件前，gitwatch 会把原内容保存在本地数据目录的 recovery/<preview-uuid>/files/ 下。目标目录中额外存在的文件不会被删除。

如果恢复中途停止，报告会列出已写入的文件及恢复副本的位置。检查完成前，请保留报告和恢复目录。
