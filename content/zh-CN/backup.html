选择要备份的文件

添加文件备份任务并选择源目录。在包含列表中填写相对于项目根目录的文件或目录，每行一个，例如：

AGENTS.md
.agents

包含项使用路径；排除项使用 glob 模式，同样每行一个，路径分隔符使用正斜杠。排除整个目录可填 .agents/upstream，排除任意层级的 Markdown 文件可填 **/*.md。排除规则优先。

源目录不必是 Git 仓库。普通备份只读取文件，把副本提交到独立存储，不会在源仓库中暂存、提交或推送。

历史与文件范围

每个备份任务在所属工作空间的备份仓库中有独立分支，快照包含清单和选中的文件。绝对源路径只保存在本机，另一台电脑可以使用不同目录。

可以选择被源项目 Git 规则忽略的文件，但仍会排除 Git 元数据以及内置的凭据、缓存路径。单文件上限为 16 MiB，单次扫描总量为 128 MiB，最多 10,000 个文件。

普通备份会保留源目录中已经消失的文件的最近备份。修改包含或排除规则后，不再属于选择范围的文件会从最新快照移除，旧的 Git 历史仍然保留。双向同步则会传播选中文件的删除。

符号链接

跟随符号链接默认关闭。启用后，会把链接目标中的实际文件备份到链接的相对路径下，即使目标位于项目之外。不存在的目标会跳过，循环链接或无法读取的目标会报错。恢复目标必须是普通路径，双向同步不支持跟随链接。

上传备份

创建工作空间时填写专用远程仓库地址，再在工作空间设置中配置自动上传。认证由 Git 处理。上传失败时，本地快照会保留，可稍后重试。

上传发送已保存的快照；尚无快照时会先创建一次。如果已经有快照，请先执行备份来保存新的本地修改，再上传。推送不会强制覆盖历史。需要合并其他电脑的修改时，请使用双向同步；上传操作不会下载文件。

任务名与分支

同一工作空间内，任务名忽略大小写和首尾空白后不能重复。新备份分支默认使用任务名，空白替换为连字符。重命名时同步重命名绑定的本地和远程分支，并保留历史。远端分支保护或重名可能阻止重命名。

在另一台电脑上恢复

  1. 创建工作空间，填写相同的备份仓库地址。
  2. 点击恢复远程备份，等待列表加载，选择分支和本地目标目录。
  3. 进入预览，检查文件和目标目录。新任务此时处于暂停状态。
  4. 勾选确认框，点击确认恢复，等待完成提示后再检查目标目录。

读取列表或创建任务本身不会写入源文件。已有任务可使用任务的恢复入口；需要恢复某个历史版本时，打开历史记录。目标目录中的额外文件会保留，链接路径不能作为恢复目标。

预览在 24 小时后过期，目标文件变化后也需要重新预览。覆盖文件前会在数据目录保存恢复副本。如果恢复中断，请保留这些副本并检查活动记录。

恢复完成后任务仍然暂停。启动普通备份可上传本地修改；如需两台电脑持续互相更新，请启用双向同步。
