语言与时间

支持英语和简体中文。首次启动跟随系统语言，不支持的语言回退为英语。在桌面语言菜单中选择语言，或在 TUI 中按 F3，可以保存偏好。

gitwatch --lang en --help
gitwatch --lang zh-CN tui
gitwatch --lang zh-CN desktop

优先级依次为 --lang、GITWATCH_LANG、已保存偏好、系统语言，最后回退英语。命令名、选项名和 JSON 字段保持一致；路径、文件内容及 Git 自身消息保持原样。

仓库提交时间使用系统的本地时区，显示格式为 YYYY-MM-DD HH:MM:SS。日期顺序目前固定，尚未跟随系统的地区格式偏好。

本地应用数据

数据保存在系统的本地应用数据目录，包括任务配置、偏好、备份历史和恢复副本。使用独立数据目录可以运行：

gitwatch --data-dir ./gitwatch-data desktop

也可以设置 GITWATCH_DATA_DIR。数据目录应放在被备份项目之外。同一数据目录同时只能供一个桌面或 TUI 实例使用。完整备份本地数据前，请先退出 gitwatch，并把 Git 仓库与配置一起保留。

脚本可以使用 --json 获取结构化 CLI 输出，当前 schema_version 为 1。

工作空间数据与共享设置

下一次发布的桌面应用和 TUI 支持在同一数据目录中保存多个工作空间。默认工作空间直接使用原有数据，不搬移文件；自定义工作空间的数据保存在 spaces/ 中，名称和当前选择记录在 spaces.json 中。

语言、启动时最小化到托盘和新版本提示属于整个应用。任务、任务顺序、启动状态、拉取截止时间、备份历史和备份远程各自属于对应工作空间。切换工作空间不会停止已启动的任务。

备份或搬移应用数据时，请先退出 gitwatch，再复制整个数据目录，包含 spaces/ 和 spaces.json。从界面移除空工作空间后，它的文件仍会保留。

更新官方发布版

gitwatch self update --check
gitwatch self update
gitwatch self uninstall

这些命令已在源码版本中实现，将包含在下一次发布中；v0.1.0 尚不支持。从官方压缩包解压后，请保留程序旁的 gitwatch-install.json。没有安装凭据的旧目录需要重新下载完整压缩包。

更新器会验证下载内容、检查新程序能否启动，再一起替换 CLI 和桌面程序。独立安装的 CLI 也能更新。更新使用包含 TUI 的官方构建，不保留自定义 Cargo 功能选择，也不会给仅 CLI 的安装补装桌面程序。

操作前先停止其他 gitwatch 进程。桌面应用需要从托盘菜单选择退出，关闭窗口仍会后台运行。更新与卸载会列出受影响的程序并要求确认；脚本可以使用 --yes。卸载会保留设置、备份历史、恢复数据和许可证说明。

Cargo 安装请使用 cargo install gitwatch --locked --force，并加上原来的功能选项。源码安装请先更新源码，再重新执行源码安装命令。使用 cargo uninstall gitwatch 卸载 Cargo 安装。其他包管理器安装应通过对应包管理器更新与卸载。

恢复中断的更新

gitwatch self update --recover

可执行文件旁的 .gitwatch-recovery 目录会保留旧程序，直到更新完成。如果 CLI 本身缺失，先将保存的旧二进制复制回安装目录，再运行恢复命令。更新不会自动降级；需要指定某个已发布版本时，使用 --version <版本号>。

新版本提示

有新的稳定版时，桌面应用和 TUI 会显示提示，交互式 CLI 则向 stderr 输出更新命令。检查在后台进行，结果缓存一天，不会自动安装。网络失败不会中断任务。

设置 GITWATCH_NO_UPDATE_CHECK=1 可关闭自动检查，显式运行 self update --check 仍然有效。JSON 和重定向后的 CLI 输出不会混入自动更新提示。
