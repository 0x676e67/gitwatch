为备份任务启用同步

先在另一台电脑上恢复同一份备份，确保两个任务使用相同的远程备份分支。普通备份在启用同步前仍然只负责上传。

  1. 选中任务，打开双向同步…。
  2. 选择策略和远端检查间隔。默认使用 Rebase，每 60 秒检查；间隔范围为 10 至 86,400 秒。
  3. 点击预览首次同步，检查新增、替换和删除。
  4. 勾选确认框，点击确认同步变更。
  5. 点击启动自动运行。每台需要交换修改的电脑都要分别启用同步。

自动运行会保存本地修改、获取备份分支、合并历史、写入选中的文件并推送。即使本机没有修改，也会定期检查远端。同步可替换和删除选中的文件，其他文件和源项目的 Git 历史会保留。

选择合并方式

策略行为
Rebase（默认）在远端历史上重放本地备份提交，重放后的提交 ID 会变化。
Merge可以快进时直接更新，否则创建合并提交。
仅快进双方都有新提交时暂停，等待处理。

同步遵循 Git 历史关系，不按文件时间戳判断，也不会强制推送覆盖远端历史。离线期间的修改先保留在本地，后续检查成功后再同步。

处理冲突

  1. 同步暂停后，打开处理同步问题…。
  2. 选择文件，比较本地、远端和共同基线内容。
  3. 选择保留本地文件、采用远端文件或编辑合并内容。手动编辑后，勾选已解决并保存。二进制或较大文件使用本地/远端选择。
  4. 处理完其他文件后，点击继续合并。
  5. 检查并确认最终变更，再启动自动运行。

合并在独立备份仓库中进行，不需要在源项目中执行 rebase 来处理备份冲突。

使用远端替换本地文件

如果确定要放弃选中文件的本地修改，点击使用远端版本…，检查预览中的替换和删除后再确认。这是主动选择的恢复操作，不是日常同步策略。

程序会保留恢复副本。可用时，撤回上次同步…会预览上次同步的反向变更，检查并确认后再继续工作。

文件边界

同步不支持跟随符号链接。遇到文件与目录冲突或不安全的目标路径时会停止，不会递归删除目录。预览后本地文件发生变化时，需要重新预览。
