Select the files to save

Add a file backup task and choose its source directory. Enter project-relative files or directories in the include list, one per line. For example:

AGENTS.md
.agents

Include entries are paths. Exclusions are glob patterns, also one per line, with forward slashes. To omit a whole directory, enter .agents/upstream. To omit Markdown files anywhere, enter **/*.md. Exclusions take precedence.

The source need not be a Git repository. Ordinary backups read its files and commit copies to separate storage. They do not stage, commit or push the source repository.

History and file boundaries

Each backup task has its own branch in the workspace's backup repository. Snapshots contain a manifest and the selected files. Absolute source paths stay local, so another computer can use a different directory.

Files ignored by the source project's Git rules can be selected, but Git metadata and built-in credential/cache exclusions still apply. Limits are 16 MiB per file, 128 MiB per scan and 10,000 files.

Ordinary backups retain previously saved files when those files disappear from the source. Changing include or exclude rules removes files outside the new selection from the latest snapshot, while preserving Git history. Two-way sync also propagates deletions of selected files.

Symbolic links

Follow symbolic links is off by default. Enabling it backs up the target's actual files under the link's relative path, including targets outside the project. Missing targets are skipped; cycles and unreadable targets cause an error. Restore destinations must be ordinary paths, and two-way sync cannot follow links.

Upload backups

Create a workspace with a dedicated remote repository, then configure automatic uploads in its workspace settings. Credentials come from Git. Upload failures leave local snapshots available for retry.

Upload sends the saved snapshot. It creates one first if none exists; otherwise use the backup action to capture new local changes before uploading. Pushes are never forced. To integrate changes from other computers, use two-way sync. Upload does not download files.

Names and branches

Task names are unique within a workspace, ignoring case and surrounding whitespace. A new backup branch uses the task name with whitespace replaced by hyphens. Renaming also renames the configured local and remote branch, preserving history. Branch protection or a collision can prevent a rename.

Restore on another computer

  1. Create a workspace with the same backup repository URL.
  2. Choose Restore remote backup. Wait for the list, select a branch and choose the local destination.
  3. Continue to the preview and review the files and destination. A new task is created paused.
  4. Check the confirmation box and choose Confirm restore. Wait for completion before checking the destination.

Loading the list or creating a task does not write source files. For an existing task, use its restore action; use History to restore a saved version. Extra destination files are left alone. Linked destinations are rejected.

Previews expire after 24 hours and must be refreshed if destination contents change. Recovery copies are kept in the data directory before overwriting files. If restoration stops partway through, keep those copies and inspect the activity report.

The restored task stays paused. Start regular backups to upload local changes, or enable two-way sync to keep both computers updated.
