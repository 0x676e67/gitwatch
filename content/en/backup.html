Select the files to save

Workspace backups copy selected files to a dedicated bare Git repository. Each workspace has its own branch. Your source directory does not need to be a Git repository, and gitwatch does not stage or commit anything in it.

gitwatch workspace add ./project-a --name project-a --include notes.md --include notes
gitwatch workspace add ./project-b --name project-b --include notes.md --include notes
gitwatch workspace list
gitwatch workspace backup project-a
gitwatch workspace watch --all

Replace these paths and selections with your own. Adding a workspace saves its settings; the backup command makes a single backup, while watch --all keeps watching registered workspaces.

Branches and file boundaries

Each workspace has a stable UUID and a branch named workspaces/<uuid> by default. A backup contains manifest.json and files/<project-relative-path>. Absolute source paths stay in local configuration, so another machine can bind the same backup to a different directory.

You can select files ignored by the source project's Git rules. Git metadata and known credential or cache paths are still excluded. Symlinks and Windows reparse points are rejected. A scan is limited to 16 MiB per file, 128 MiB of content and 10,000 files.

If a selected file disappears, its last backup is retained and reported. A missing source directory produces an error instead of a new backup. Workspace backups therefore do not mirror source deletions in the same way as watch mode.

Use a remote backup repository

gitwatch workspace remote https://github.com/you/private-backup.git --auto-push
gitwatch workspace fetch

Use a repository appropriate for the contents you are backing up. Leave out the remote configuration for local-only backups. Fetch retrieves history without restoring files. Push never uses force; if histories diverge, your local backup remains intact and you must reconcile the histories yourself.

Preview, then restore

On another machine, configure the remote and fetch its branches, then bind a workspace to a local directory:

gitwatch workspace remote https://github.com/you/private-backup.git
gitwatch workspace fetch
gitwatch workspace import workspaces/<uuid> ./local-project
gitwatch workspace history <uuid>
gitwatch workspace restore <uuid> --preview
gitwatch workspace restore <uuid> --plan <preview-uuid> --show notes.md
gitwatch workspace restore <uuid> --plan <preview-uuid> --confirm

Replace <uuid> with the workspace UUID and <preview-uuid> with the preview ID returned by the command. Angle brackets mark placeholders; do not type them literally. Import leaves the workspace paused so you can inspect and restore before starting a watcher.

  1. Create a preview and review the files that would change.
  2. Inspect file contents using --show, or use the desktop preview.
  3. Confirm that exact preview when you are ready to write files.

A preview expires after 24 hours. If destination contents change, create a new preview. Before replacing files, gitwatch saves their previous contents under recovery/<preview-uuid>/files/ in the local store. Extra destination files are left alone.

If a restore stops partway through, its report identifies the files written and the recovery copies. Keep the report and recovery directory until you have checked the result.
