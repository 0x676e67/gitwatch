Add your first task

gitwatch desktop
  1. Click Add task and choose Workspace backup, Git watch or Scheduled pull.
  2. Give it a name and select the source directory. Set the options for that mode.
  3. Save the task. It appears in the list, stopped.
  4. Select it and click Run once to try it, or Start to keep it running.

Manage running tasks

Stop a running task before editing or removing it.

The task list remains visible while you add tasks or open settings. Select any task to return to its details. Drag the six-dot handle to reorder tasks; the order is saved. Drag near the list's edge to scroll, or press Escape to cancel the drag.

ControlWhat it does
Start / StopEnable or stop the task's worker. Started tasks resume the next time you open the desktop app or TUI.
Run onceRun a stopped task once, or request an immediate run from a started task. It does not change its startup state.
RefreshReload tasks and request fresh repository information.
ActivityRead operation results and errors. Check here when an update fails.

If an operation is already in progress, a requested run waits until it finishes. Repeated pending requests are combined. A manual pull starts a new countdown when it finishes.

Keep separate task lists

Multi-workspace support is part of the next release. v0.2.0 has a single task list.

The Default workspace is ready to use when you first open the app. Tasks and backup history from v0.2.0 stay there, with their startup settings and pull schedules intact.

  1. Click New workspace.
  2. Enter a name and the URL of a dedicated backup repository. A remote is required for every custom workspace.
  3. Save, then choose the new workspace from the menu before adding tasks.

Each workspace has its own task list and backup history. A Workspace backup is still a task type: you can add backup, watch and pull tasks to any workspace. The workspace's backup remote is separate from the remote used by a watch or pull task.

Switching only changes the list you see. Started tasks in other workspaces continue running, and they all resume when you reopen the app. The selected workspace and saved pull deadlines are remembered too.

The default workspace is local: its backup remote cannot be changed in the interface. An existing remote from an older version is preserved. For a custom workspace, use Backup settings to change its remote, choose automatic upload, or fetch and import backup branches.

Rename workspace changes the name without moving data. Remove workspace is available only when the current workspace has no tasks; its backup data stays on disk. The default workspace cannot be renamed or removed.

Browse and restore backups

Select a workspace backup to open its history. Select a revision, preview the files, then review their contents before confirming a restore. Previewing alone does not write to the source directory. See the restore workflow for recovery files and preview expiry.

Read repository information

The detail panel shows the repository link, branch, latest commit, commit and contributor counts, tags and tracked files. Click the repository link to open it in your browser.

Counts come from local Git at HEAD, including merge commits. A shallow clone may have incomplete history. Text line counts include comments and blank lines; file types are grouped by extension, not by a language parser. Binary files are counted separately.

Information refreshes in the background while the details are open. Use Refresh information to request it immediately. Gathering these statistics does not make network requests. Commit dates are displayed in local time.

Keep tasks running in the tray

Closing or minimizing the window keeps tasks running in the tray. Click the tray icon to reopen the window. Right-click the icon and choose Quit to stop tasks and exit.

Under Settings, enable Start minimized to tray to hide the window on later launches. This is off by default. Tasks you started resume either way. No system service is installed; gitwatch needs to be running for tasks to run.
