Language and time

English and Simplified Chinese are supported. On first launch, gitwatch follows the system language and falls back to English for other languages. Choose a language from the desktop menu or press F3 in the TUI to save your preference.

gitwatch --lang en --help
gitwatch --lang zh-CN tui
gitwatch --lang zh-CN desktop

The order of precedence is --lang, GITWATCH_LANG, saved preference, system language, then English. Command names, option names and JSON fields stay the same in both languages. Paths, file contents and Git's own messages are kept as they are.

Repository commit dates use the system's local timezone and are displayed as YYYY-MM-DD HH:MM:SS. The date order is fixed; it does not yet follow regional date-format preferences.

Local application data

The store lives in your system's local application data directory. It contains task configuration, preferences, backup history and recovery files. To use a separate store:

gitwatch --data-dir ./gitwatch-data desktop

You can also set GITWATCH_DATA_DIR. Keep the store outside the projects you are backing up. Only one desktop or TUI instance can use a data directory at a time. Quit gitwatch before copying the entire store for a backup; keep the Git repository and configuration together.

For scripts, --json produces structured CLI output with schema_version: 1.

Workspace data and shared settings

In the next release, the desktop and TUI can keep separate workspaces inside one data directory. The default workspace uses the existing store in place. Custom workspaces keep their data under spaces/; their names and the current selection are saved in spaces.json.

Language, start-in-tray preferences and update notices apply to the whole app. Tasks, their order, startup state, pull deadlines, backup history and backup remote belong to each workspace. Switching workspaces leaves started tasks running.

To back up or move the application data, quit gitwatch and copy the entire data directory, including spaces/ and spaces.json. Removing an empty workspace from the interface leaves its files in place.

Update an official release

gitwatch self update --check
gitwatch self update
gitwatch self uninstall

These commands are in the source build and will be included in the next release. They are not available in v0.1.0. Keep gitwatch-install.json beside programs extracted from an official release archive. Older folders without this receipt need a fresh download.

The updater verifies the download and checks that the new programs can start, then replaces the CLI and desktop together. A standalone CLI can update itself, too. Updates use the official build with TUI support: they do not preserve custom Cargo features or add a desktop binary to a CLI-only installation.

Stop other gitwatch processes first. For the desktop, choose Quit from the tray menu; closing the window leaves it running. Update and uninstall list the affected programs and ask for confirmation. Use --yes in scripts. Uninstall preserves settings, backup history, recovery data and license notices.

For Cargo installations, run cargo install gitwatch --locked --force with your original feature options. For a source installation, pull the source and repeat the source install command. Use cargo uninstall gitwatch to remove a Cargo installation. Other package-managed installations should use their package manager.

Recover an interrupted update

gitwatch self update --recover

The .gitwatch-recovery folder beside the executable keeps the previous programs until the update finishes. If the CLI is missing, copy its saved binary back to the installation directory before running recovery. Updates never downgrade automatically. To request a specific published version, use --version <version>.

New version notices

The desktop and TUI show a notice when a newer stable version is available. Interactive CLI sessions print the update command to stderr. Checks run in the background, are cached for a day and do not install anything. Network failures do not interrupt tasks.

Set GITWATCH_NO_UPDATE_CHECK=1 to disable automatic checks. Explicit self update --check still works. JSON and redirected CLI output do not include automatic notices.
