Watch a file or directory

gitwatch ./notes
gitwatch -s 2 -r origin -b main ./notes
gitwatch -f -m "Notes: %d" ./notes
gitwatch watch ./notes --once

The target must be inside a Git repository. The second command waits two seconds after changes settle, then commits and pushes to origin on main. The third commits existing changes at startup and uses a custom message; %d expands to the date and time. The last command makes one pass and exits.

What gets committed

Only the selected file or directory is committed. Git ignore rules apply, and deletions are recorded. If you have staged changes inside that path, gitwatch waits for you to handle them. Staged changes elsewhere are left alone.

Without -f, existing changes become the starting baseline. A later change triggers a commit. gitwatch uses filesystem events and periodically checks file contents. Pass --polling if filesystem notifications are unreliable.

gitwatch waits while another Git operation is in progress. Finish or abort that operation yourself before expecting new automatic commits.

Coming from the shell version

OptionBehavior
-RPull with rebase before pushing. Off by default.
-xFilter events that trigger a commit. It does not exclude files from that commit.
-cRun a command to generate the commit message. No shell is used unless you invoke one explicitly.
-h / -CThese flags take no argument.

Run gitwatch watch --help for the complete option list. Failed commands return a nonzero exit code. This is an independent implementation; check the options you rely on when replacing a shell-script installation.
