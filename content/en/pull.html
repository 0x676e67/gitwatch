Set a schedule

gitwatch pull ./upstream --url https://github.com/gitwatch/gitwatch.git --every 3600
gitwatch pull ./existing-repo --remote origin --once
gitwatch pull ./existing-repo --strategy merge --every 600
gitwatch pull ./existing-repo --strategy rebase --once

The first command clones into an absent or empty directory, then checks for updates every hour. The second updates an existing checkout once. Use --every to set the interval in seconds.

In the desktop app, add a Scheduled pull task and set its directory, remote, interval and strategy. Leave the clone URL empty for an existing repository. Save, then click Start. The task card shows the time until the next attempt.

Choose a pull strategy

StrategyWhen history diverges
ff-only · defaultRefuses the update. Use this when you want history changes to remain explicit.
mergeCreates a merge commit. Fast-forwards if no merge is needed.
rebaseReplays local commits on remote history, changing their IDs. Use for unpublished commits.

Choose the strategy from the desktop form's dropdown. In the TUI, focus the strategy field and use Left/Right or Space. Merge and rebase require your Git author identity.

The selected strategy overrides Git's pull preferences for that invocation. It does not change repository or global Git configuration. Existing tasks without a saved strategy use ff-only.

Handle failed pulls

gitwatch skips dirty checkouts and refuses to continue after a branch switch. It does not stash changes, reset your work or force-update the checkout. Operation results and errors appear in the interactive interface's activity log or the CLI output.

Ordinary failures, including network errors, retry at the configured interval. If a merge or rebase leaves an unfinished operation, the task stops. Resolve and continue the operation using Git, or abort it with the matching command:

git merge --abort
# Or, for an unfinished rebase:
git rebase --abort

Run only the command that matches the operation you want to abandon. Check the repository, then restart the task.

Restarts and manual runs

The desktop and TUI save the next run time. After restarting, they continue the remaining countdown. If it has already passed, the task runs once immediately, then resumes its normal interval.

Run once is available for started and stopped tasks. It never creates a second worker for the same started task. After a manual pull finishes, the countdown starts again. A fatal Git-operation error keeps the task stopped across app restarts.
