Create a pull task

  1. Choose Add task, then scheduled pull.
  2. Select an existing checkout. To clone instead, choose an empty or absent destination and supply the clone URL.
  3. Set the remote, optional branch, interval and pull strategy.
  4. Save, then choose Pull now to verify it or start automatic runs.

The clone URL is used only for the first clone. Later updates use the configured remote. The next pull countdown and started state survive app restarts.

Pull strategies

Fast-forward only is the default for scheduled pulls and refuses divergent history. Merge permits a merge commit; Rebase replays local commits on the fetched branch. Select the behavior in the task form.

If a pull cannot finish

Check the activity log and repository state. Commit or stash uncommitted work before pulling. For a merge or rebase conflict, pause the task, resolve the checkout with your usual Git tools, and run it again.

Scheduled pulls change a regular source repository. For selected files stored in gitwatch's separate backup repository, use two-way sync instead.
