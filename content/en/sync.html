Enable sync for a backup task

First restore the same backup on the other computer. Both tasks must use the same remote backup branch. Ordinary backups remain upload-only until you enable sync.

  1. Select the task and open Two-way sync….
  2. Choose the strategy and remote check interval. Defaults are Rebase and 60 seconds; the interval range is 10 to 86,400 seconds.
  3. Choose Preview first sync and review additions, replacements and deletions.
  4. Acknowledge the changes, then choose Confirm sync changes.
  5. Choose Start automatic runs. Enable sync separately on each computer that should exchange changes.

Automatic runs save local changes, fetch the backup branch, integrate history, apply selected files and push. Remote checks happen even without local edits. Sync can replace and delete selected files; other files and the source project's Git history are kept.

Choose how histories combine

StrategyBehavior
Rebase (default)Replay local backup commits on remote history. Replayed commit IDs change.
MergeFast-forward when possible; otherwise create a merge commit.
Fast-forward onlyStop for attention if both sides have new commits.

Sync follows Git ancestry, not file timestamps. It does not force-push over remote history. Offline changes remain local until the next successful check.

Resolve a conflict

  1. When sync pauses, open Resolve sync….
  2. Select a file and compare local, remote and common-ancestor contents.
  3. Choose Keep local file, Keep remote file, or Edit merged text. For edited text, mark the conflict resolved and save. Binary and large files use the local/remote choices.
  4. Resolve the remaining files, then choose Continue integration.
  5. Review and confirm the resulting changes, then start automatic runs again.

Integration happens in the private backup repository. Do not run a rebase in your source project to resolve this backup conflict.

Replace local files with the remote version

To discard local changes to selected files, choose Use remote version…. Review the preview, including deletions, then explicitly confirm. This is a recovery choice, not the normal sync strategy.

Recovery copies are kept. When available, Undo last sync… previews a reversal of the last applied sync. Review and confirm before resuming work.

File boundaries

Sync cannot follow symbolic links. File/directory collisions and unsafe destinations stop the operation instead of recursively deleting a directory. If local contents change after preview, refresh the preview.
