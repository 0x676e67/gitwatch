CI checks CLI, TUI, desktop and combined builds on Windows, macOS and Linux. Tests use temporary repositories and local remotes. The terminal UI uses Ratatui; the desktop uses egui/eframe.

Report bugs or propose changes in GitHub issues. Include the gitwatch version, operating system, task mode, command or steps, and the relevant error message. Remove private paths, remote credentials and file contents before sharing logs.

Release workflow

The Release workflow builds archives containing the CLI and desktop binaries, along with SHA-256 checksums. Native installers, signing, notarization and automatic conflict resolution are not included.

A v<version> tag must match Cargo.toml and point to a commit on main. Pushing it publishes a GitHub Release after checks pass. Crates.io uploads use Trusted Publishing through release.yml and the crates-io environment. Already published crate versions are skipped; a new crate's first upload must be done locally before configuring trust.

To rehearse, run Release from the Actions tab with publish disabled. To publish an existing tag manually, select that tag and enable publish. Keep publish_crate disabled for a GitHub-only release.

Documentation

The site lives on the gh-pages branch. English and Chinese pages share one template and stylesheet. Python builds static HTML without third-party packages. Local preview instructions are in that branch's README.

Screenshots use dedicated demonstration repositories. No real task data is included. Update both language versions when a workflow changes.
